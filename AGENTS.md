# Правила работы

## Язык

- Проект ведём на русском языке: общение, документация и пояснения к изменениям — на русском.
- Код, имена переменных, функций и файлов, комментарии в коде — на английском.
- Русский текст в коде допускается только в значениях переводов i18n. Документация пишется на русском.
- Все пользовательские строки UI, включая ошибки, уведомления, подсказки и сообщения валидации, выводим через i18n. Не добавляем текст интерфейса напрямую в компоненты.
- Поддерживаем два языка: русский (`ru`) и английский США (`en-US`). При добавлении или изменении строки обновляем оба перевода; ключи переводов — на английском.
- На бэкенде i18n не используем: сообщения ошибок, логи и прочие сообщения пишем непосредственно строками на английском. Для отображения ошибок бэкенда в UI используем локализованные сообщения по коду ошибки; исходный текст ошибки пользователю не показываем.

## Структура

- `apps/web` — Nuxt 4, Vue, Nuxt UI и Pinia.
- `apps/api` — NestJS/Fastify и отдельный worker; `apps/gateway` — отдельный HTTP-процесс.
- `packages/core` — чистый домен; `packages/contracts` — общие контракты Zod; `packages/client` — HTTP SDK.
- Prisma и миграции находятся в корне. Описание архитектуры — в `dev_docs/`, инструкции запуска — в `README.md`.

## Разработка и проверки

- Используем Node.js 24+ и pnpm; общие версии зависимостей задаём в catalog файла `pnpm-workspace.yaml`.
- Соблюдаем существующие границы пакетов и стиль кода. Изменения делаем в рамках задачи.
- После изменений кода запускаем `pnpm check` и относящиеся к изменению тесты: `pnpm test:unit`, `pnpm test:web`, `pnpm test:integration` или `pnpm test:e2e`. Для интеграционных тестов нужен Docker.
- Изменения схемы БД оформляем миграциями Prisma. Не используем production `DATABASE_URL` локально и не добавляем секреты в репозиторий.
